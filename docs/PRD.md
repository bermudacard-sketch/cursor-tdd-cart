## 1. 개요

장바구니에 담긴 품목(단가·수량)을 합산하고, **문턱 할인**(소계 50,000원 초과 시 10%)과 **VIP 추가 할인**(문턱 할인 후 5%)을 순서대로 적용하여 최종 결제 금액을 계산하는 시스템이다.

- **Entity** (`src/cart.py`): 순수 할인 계산 로직. Flask 등 Boundary를 import 하지 않는다.
- **Boundary** (`src/app.py`): Flask 주문 폼. Entity를 호출하여 결과를 반환한다.

본 PRD의 요구사항은 MomTest Product Discovery에서 도출된 **테스트 가능한 계약**만 포함한다. 근거가 없는 동작은 OOS(Out of Scope)로 명시하며 구현하지 않는다.

---

## 2. 배경 및 문제 정의

### 2.1 발견된 실제 사례

| 출처 | 내용 |
|------|------|
| 인터뷰 (2024-03-12) | A 3개(12,000원) + B 1개(30,000원) = 66,000원. 5만 원 넘으면 10% 할인 → 기대 59,400원 |
| 인터뷰 | VIP 고객은 문턱 할인 **후** 추가 5% 할인. 순서: 문턱 → VIP 고정 |
| 주문 #1107 | 소계 60,000 → 결제 54,000 (10% 할인) |
| 주문 #1042 | 소계 48,000 → 할인 없음 |
| 엑셀 검산 | 66,000 × 0.9 = 59,400 (ROUND); VIP: 59,400 × 0.95 = 56,430 |

### 2.2 확인된 버그·CS 이슈

| 이슈 | 현상 | 기대 동작 |
|------|------|-----------|
| 음수 수량 | 수량 -1 입력 시 화면 합계 0원 표시 | 오류 또는 거부 (0원 반환 금지) |
| 빈 제출 | `items` 없이 제출 시 HTTP 500 | 명시적 4xx 오류 응답 |

### 2.3 미확인·비범위

- 쿠폰·배송비·포인트·세금: 인터뷰·주문 사례에 언급 없음
- 소계 정확히 50,000원: “넘으면”만 확인, 포함 여부 미확인 (→ OOS-1)

## 3. 목표

1. 인터뷰·주문·검산 근거가 있는 할인 규칙을 **계약 ID**로 고정하고 pytest로 검증한다.
2. CS에서 보고된 입력 오류(음수 수량, 빈 제출)를 명시적 오류로 처리한다.
3. 근거 없는 기능(쿠폰, 배송비 등)은 구현하지 않아 과잉 개발을 방지한다.

### 비목표 (Non-Goals)

[Report/02.REPORT.md](../Report/02.REPORT.md) OOS 표 전체 — 특히 쿠폰·배송비·품목별 개별 할인·VIP 우선 순서·소수 처리·5만 이하 VIP 단독 할인.

## 4. 사용자 및 사용 시나리오

| 역할 | 시나리오 |
|------|----------|
| 운영·CS | 주문 금액이 엑셀 검산과 일치하는지 확인 |
| 개발자 | `calculate(items, vip)` API로 결제액 산출 |
| 고객 (Boundary) | 웹 폼에 품목·수량 입력 후 주문 제출 |

### 대표 시나리오

1. **일반 고객 — 문턱 할인 적용**: A×3 + B×1 = 66,000 → 59,400원
2. **일반 고객 — 문턱 미달**: 소계 48,000 → 48,000원 (할인 없음)
3. **VIP 고객 — 이중 할인**: 66,000 → 59,400 → 56,430원 (문턱 후 VIP)
4. **잘못된 입력**: 음수 수량 → `ValueError`; 빈 장바구니 제출 → 4xx 응답

## 5. 기능 요구사항 (Acceptance Criteria)

| ID | 요구사항 | 근거 | 계층 |
|----|----------|------|------|
| **AC-1** | 소계 = Σ(단가 × 수량). 예: (12,000×3)+(30,000×1) = 66,000 | L1 | Entity |
| **AC-2** | 소계 **>** 50,000이면 `round(소계 × 0.9)` 반환 (10% 할인) | L1 | Entity |
| **AC-3** | 소계 **≤** 50,000이면 소계 그대로 반환 (할인 없음) | L1 | Entity |
| **AC-4** | VIP이고 문턱 할인 적용 후 금액 P이면 `round(P × 0.95)` 반환 | L2 | Entity |

### 계산 예시

| 입력 (소계) | VIP | 기대 결제액 | 적용 계약 |
|-------------|-----|-------------|-----------|
| 66,000 | false | 59,400 | AC-1, AC-2 |
| 60,000 | false | 54,000 | AC-2 |
| 48,000 | false | 48,000 | AC-3 |
| 66,000 | true | 56,430 | AC-1, AC-2, AC-4, INV-3 |

### 할인 적용 순서

```
소계 계산 (AC-1)
  → 문턱 할인 여부 판단 (AC-2 / AC-3)
  → VIP이면 문턱 적용 후 금액에 5% (AC-4, INV-3)
  → 최종 결제액 (원 단위 round)
```

## 6. 불변식 (Invariants)

어떤 유효 입력에서도 깨지면 안 되는 규칙이다.

| ID | 불변식 | 검증 아이디어 |
|----|--------|---------------|
| **INV-1** | 최종 결제액 ≥ 0 | 모든 확정 AC 입력에서 `>= 0` |
| **INV-2** | 할인 적용 시 결제액 ≤ 소계 | AC-2~4 케이스에서 `pay ≤ subtotal` |
| **INV-3** | VIP 추가 할인은 문턱 할인 **이후** 금액에만 적용 (순서: 문턱 → VIP) | 66,000+VIP: `59400×0.95` ≠ `66000×0.95×0.9` |

---

## 7. 오류 처리 (Error Contracts)

| ID | 조건 | 기대 동작 | 계층 |
|----|------|-----------|------|
| **E-1** | `price` 또는 `qty`가 음수 | `ValueError` (인덱스 포함). 0원 반환 금지 | Entity |
| **E-2** | `items`가 `None` | `TypeError` | Entity |
| **E-3** | `items`가 빈 리스트 `[]` | HTTP 500이 아닌 **4xx + 명시적 메시지** | Boundary |

---

## 8. Out of Scope (OOS)

계약 ID가 없는 동작은 **구현하지 않는다**.

| OOS ID | 제외 동작 | 제외 이유 |
|--------|-----------|-----------|
| OOS-1 | 소계 = 50,000일 때 10% 할인 | 정확히 5만 원 사례·검산 없음 |
| OOS-2 | 쿠폰 할인 | 언급 없음 |
| OOS-3 | 배송비 | 언급 없음 |
| OOS-4 | 포인트·등급·세금 | 언급 없음 |
| OOS-5 | 품목별 개별 10% 할인 | 항상 소계 기준 |
| OOS-6 | VIP 우선 → 문턱 순서 | “문턱 → VIP”만 근거 |
| OOS-7 | 음수 수량 시 0원 표시 | CS 기대는 오류·거부 |
| OOS-8 | 소수 원·소수 수량 | 실제 사례 없음 |
| OOS-9 | 5만 이하 VIP 단독 5% | VIP 사례가 문턱 할인 이후에만 있음 |

## 9. 근거 레벨

| 레벨 | 의미 | 예시 |
|------|------|------|
| L0 | 버그·실패 사례 (수정 대상) | 수량 -1 → 0원, 빈 제출 500 |
| L1 | 다중 독립 근거 (주문·인터뷰·검산 일치) | 소계 합산, 문턱 10% |
| L2 | 단일 맥락·순서 의존 | VIP 5%, 문턱→VIP 순서 |
| L3 | 도메인 추론 (AC에서 파생) | 결제액 ≥ 0, pay ≤ subtotal |
